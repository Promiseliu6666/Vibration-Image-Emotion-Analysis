# 校园 / 家庭局域网部署

这是一个供少量用户共享的学习空间。共享查看账号能够看到这个空间的全部设备和记录；它不是每个用户数据隔离的多租户系统。

## 启用流程

1. 在服务器电脑运行 `start.cmd`，打开 `http://127.0.0.1:8000/static/dashboard.html?v=7`。
2. 管理员进入“系统设置”，用当前密码更改为至少 10 个字符的新密码。
3. 勾选“允许同一局域网的其他设备访问”，保存。
4. 运行 `stop.cmd`、再运行 `start.cmd`。后台会监听所有网卡的 8000 端口。
5. 系统设置显示当前局域网地址。其他电脑或手机接入可互通的 Wi-Fi，访问该地址。
6. Windows 防火墙如阻止连接，在可信网络上允许该项目的 TCP 8000 入站。校园网设备隔离需要网络管理员或自建局域网解决。

更改默认密码是开启局域网的前置条件。应用不会自行打开防火墙或把服务映射到公网。当前 HTTP 部署适用于可信局域网；互联网部署需要 HTTPS 反向代理等额外配置。

启动和停止服务不会自动打开多个浏览器标签页。`open-project.cmd` 是单独打开界面的入口。

## 账号和数据

- 管理员可登记/删除设备、管理接入密钥、创建和停用共享查看账号、设置图片保留策略。
- 共享查看账号可以浏览共享学习记录、导出 CSV、使用已配置的助手，并修改自己的密码。
- 密码仅保存 bcrypt 哈希；设备密钥仅保存 SHA-256 哈希，明文只在登记响应中显示一次。
- 停用账号、修改密码会撤销此前签发的登录凭证。密钥重新登记会使旧设备密钥失效。
- `.runtime` 包含本地运行设置与登录签名密钥，须跟随数据库一起备份并避免公开提交。
- 新增 `workspace_users`、`device_credentials` 两张表，不重建原有设备、时段与分析表。
- “学习记录”按所选设备和日期导出 CSV，使用北京时间，最多 90 天 / 五万条。超过上限需缩小范围。

## Wi-Fi 设备接入

Wi-Fi 连上网络，不等于已开始图像采集。系统分别显示登记、网络心跳、真实画面、分析结果四个阶段。

1. 在“设备与接入”输入设备真实 MAC 地址，生成专属密钥。
2. 同一台物理设备已有 USB 数据时，可以明确选择关联它的现有记录；不同设备创建独立记录。
3. 保存页面给出的设备配置。不同设备必须使用不同密钥，设备会被限制只能向绑定的编号上传。
4. 在设备端配置 `server_url`、`hardware_id`、`device_key`，启动实际图像上传。

### 小智视觉服务兼容接口：按拍照请求分析

官方小智 SenseCAP Watcher 摄像头实现使用 multipart 的 `file` 字段发送 JPEG，HTTP 头带 `Device-Id`（MAC）、`Client-Id` 和可选 Bearer 密钥。后台提供兼容的 `/vision/explain`，返回 `text` 和分析状态。

来源：[小智官方 SenseCAP Watcher 摄像头实现](https://github.com/78/xiaozhi-esp32/blob/main/main/boards/sensecap-watcher/sscma_camera.cc)。

支持配置自定义视觉服务 URL/token 的固件，可把生成配置中的 `vision_url` 和 `device_key` 写入该功能，随后触发拍照。服务器收到真实图片后会分析并返回简短学习状态。若 15 秒内尚未完成，返回“正在后台分析”，页面继续显示进度。

这条路径是按请求拍照，不是定时连续采集。已安装的具体固件能否设置该地址，必须以它的实际配置入口为准。当前保留的 2.2.6 固件尚未完成这条路径的实机配置与断开 USB 验证，因此不能宣称设备已支持独立 Wi-Fi 持续监测。

### 持续采集固件 / 局域网网关接口

- `POST /api/device/heartbeat`：Bearer 设备密钥；建议每 20 秒发送一次。
- `POST /api/device/frame`：Bearer 设备密钥；`Content-Type: image/jpeg` 的 JPEG，或 multipart 的 `file` 字段。
- `Device-Id` 头应使用登记的物理 MAC。若声明不匹配，服务器返回 403。
- 单帧最多 4 MB，每台设备最多每 0.5 秒一帧；队列已满返回 503，客户端应退避重试。
- 返回 `request_id` 与 `analysis: queued`，表示已接收；实际分析是否完成以工作台最新状态为准。
- 网络上传不会按客户端随意提供的编号自动创建设备，必须先由管理员登记。
- 兼容旧的 `/upload/frame` 与 `/ws/device` 时，远程请求同样需要设备密钥。本机 USB 采集保持本机路径。

`network_client.py` 是实际 JPEG / 心跳客户端，可用在另一台已接相机的网关电脑：

```powershell
.\.venv\Scripts\python.exe network_client.py --config private-device.json --jpeg captured.jpg
```

不要把设备密钥传入 URL 或提交到仓库。网关程序需要自己获取相机的真实 JPEG；提供的客户端不会伪造画面。

## 实机验收

真正启用 Wi-Fi 采集的验收应在第二台设备或网关上完成：连接同一局域网、配置专属密钥、收到真实图像、完成分析，断开 USB 后继续产生新画面，再验证断网与恢复。

只用服务器内部的协议测试不能替代这一步。USB 原设备与网络接口已分别开发，当前硬件仍采用已验证的 USB 采集。
