# 摄像头算法配置

## 页面分工

| 页面 | 用途 |
| --- | --- |
| 算法配置 | 查看主算法、辅助能力、输出指标、适用场景和外部服务算法目录 |
| 设备配置 | 查看摄像头列表，在设备行中编辑场景、算法和检测线框并保存 |
| 实时监测 | 查看单路大画面或四画面，选择当前摄像头已配置的指标并查看结果 |

主分析算法包括幸福指数 / 振动情绪分析和疲劳检测。同一摄像头可同时启用两种算法，共用视频采集源，显示各自指标。人脸检测、稳定检测和身份识别随主算法运行，展示在辅助能力区域，无需单独启用。外部服务算法保留在算法管理页底部的“外部服务算法目录”中。

## 为摄像头配置算法

1. 在“算法配置”中点击“为摄像头配置”，或者直接打开“监测配置 → 设备配置”。
2. 在摄像头列表中找到目标设备，查看其来源和状态。
3. 在该设备行选择或输入应用场景，勾选一种或多种分析算法，按需调整检测线框开关。
4. 点击该行“保存”使配置生效，再点击“监测”进入当前的统一实时监测页面。

设备配置是摄像头算法绑定的唯一保存入口，采用行内编辑，修改后需点击“保存”；“监测”使用已保存的配置。实时监测不提供配置抽屉，修改场景、算法绑定或检测线框时，点击页面右上角“设备配置”进入设备列表。

设备配置与算法配置两个页面均恢复为提交 `d0aefa7` 的前端版本：设备页为原始表格和行内配置，算法页为原始算法卡片和外部服务列表。

## 在监测中选择画面和指标

摄像头看板与实时监测已合并，统一入口为 `/monitor/druid`。首页、`/index`、`/camera/live` 和旧看板地址 `/camera/overview` 均进入同一页面，侧边栏只保留“实时监测”入口。

进入实时监测时自动隐藏左侧导航，画面区使用腾出的宽度；点击顶部菜单按钮可随时展开导航，再次点击即可隐藏。其他页面保留原有的导航展开与收起方式。

默认显示单路大画面，在顶部“摄像头”选框中切换设备，可切换四画面、分页、重连和全屏。四画面中选中的摄像头持续运行已配置算法，其余摄像头提供原始画面预览。

顶部“查看指标”选框只列出当前摄像头已启用的心理状态或疲劳状态。选择指标后，在右侧显示对应结果；切换只影响展示，不保存算法绑定、不重启检测，也不暂停该摄像头的其他已启用算法。当前页面会临时记住每台摄像头查看的指标；切换设备时，选项和结果跟随设备配置。

点击结果栏“收起”可扩大画面，再次从“查看指标”中选择即可展开。收起和展开不会重启检测或中断预热。分析画面连接失败时，会尝试保留原始视频，并暂停展示失效的振动分析结果。

视频窗口根据收到画面的实际宽高比自动调整尺寸，完整显示全部内容，不裁剪、不拉伸，也不再提供“铺满画面”切换。桌面窗口在可用宽高内等比适配，窄屏按画面比例自动调整高度；四画面分别适配每台摄像头。浏览器尺寸变化、导航展开或结果栏收起时，窗口重新适配，不重新连接视频。

监测内容区不留外层页边，工具栏统一承载摄像头、指标、刷新和设备配置入口。单画面的设备名称只在摄像头选框中显示，画面内保留连接状态和实际分辨率；场景与来源可在选框展开时查看。四画面分别保留设备名称以区分各路画面。结果栏省去重复设备名和状态标签，人员详情默认收起。

桌面布局同时适配视频与结果：例如 640×480 的画面按 4:3 占用合适宽度，心理／疲劳结果区填满右侧剩余宽度和可用高度，不再限制为固定窄栏。结果区较宽时，综合评估与说明、疲劳分数与行为指标自动分栏，详细参数按两列排列；宽度不足时恢复纵向排列，内容过多时可在结果区滚动。

疲劳检测默认隐藏检测线框。仅启用疲劳算法时，可通过配置中的“疲劳检测线框”控制主画面的检测框；同时启用振动和疲劳算法时，主画面使用振动分析视频，疲劳指标在结果侧栏中展示。

## 连接状态与算法状态

设备配置页按来源展示本机、RTSP 和小智设备状态；小智设备显示“在线”或“未出图”，RTSP 未设置地址时显示“尚未配置地址”。进入实时监测后，以实际画面连接情况为准。

算法配置页展示算法说明和输出指标。服务是否可用、算法预热、人脸是否出现以及数据是否有效，应在实时监测中分别查看。

疲劳服务随主后端自动启动，已运行的服务会被复用。首次加载模型时需稍候；服务暂不可用时仍可保存摄像头配置，服务恢复后再进入监测。小智设备服务未启动时仍可使用本机和已配置的 RTSP 摄像头。

## 配置保存与设备来源

配置跨浏览器共享，重启后保留，保存于项目根目录 `.runtime/camera-algorithms.json`，备份时应保留该文件。旧的单算法配置继续兼容，无需重新录入或新增数据库表。

目前沿用一个本机采集源、一个 RTSP 源和多个已登记的小智 Watcher 设备。小智设备通过“小智监测 → 设备管理”接入和管理；RTSP 地址继续通过后端 `.env.dev` 中的 `CAMERA_RTSP_URL` 配置，修改连接配置后需重启后端。

原有 `/fatigue` 仍为独立的手动疲劳检测页；按摄像头已保存的算法配置查看结果时，使用统一视频监测入口。
