# 摄像头算法配置

1. 打开左侧“算法列表”，查看主分析算法、辅助能力、输出指标及原系统登记的外部服务算法。
2. 打开“摄像头列表”，在对应摄像头行选择或输入应用场景，可同时勾选幸福指数与疲劳检测，点击“保存”。
3. 点击该行“监测”，或从首页点击“按摄像头配置进入视频监测”。切换摄像头时，视频监测自动加载其算法及对应指标卡片。

当前分析算法包括幸福指数 / 振动情绪分析和疲劳检测，可应用于同一摄像头并行运行。共用一个视频采集源，显示一份视频和两种算法各自的指标。人脸检测、稳定检测和身份识别作为分析流程的辅助能力展示。旧的单算法配置自动兼容，不需要重新录入。外部服务算法继续由原有外部分析链执行。

疲劳检测默认展示原始视频，隐藏检测框、骨架连线及关键点；算法继续计算各项指标。可在摄像头配置中打开“检测线框”，或在疲劳面板临时点击“显示检测框”。临时显示状态在切换摄像头后按配置重置。

配置跨浏览器共享，重启保留，保存于项目根目录 `.runtime/camera-algorithms.json`。发布时需同步更新前后端并重启后端，备份时保留该配置文件；不需要新增数据库表。当前沿用一个本机采集源、一个已配置的 RTSP 源和多个已登记的小智 Watcher 设备。

疲劳服务随主后端自动启动，无需额外输入启动命令。首次加载模型期间稍候即可；已运行的服务会复用。摄像头共享密钥由主后端初始化，并与实际小智运行目录协调，避免首次运行时缺失共享配置。小智设备服务未启动时仍可使用本机和 RTSP 摄像头。

原有 `/fatigue` 入口仍为手动疲劳检测专页；按摄像头配置自动切换指标请使用统一“视频监测”入口。摄像头列表不改变视频源地址，RTSP 地址继续使用原有 `CAMERA_RTSP_URL` 配置。
