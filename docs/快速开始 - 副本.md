不建议现在整体改成 Vue。当前小智前端已经能用，而且涉及摄像头帧、WebSocket、文件上传、实时刷新等底层 
  行为，整体重写风险高、收益有限，也容易引入新的 503、画面不同步或设备控制问题。                      

  目前更合理的结构是：                                                                                

- 外层门户：Vue 3 + Vite，负责登录、导航、权限和菜单。                                              

- 小智系统：原生 HTML/CSS/JavaScript，独立运行在 8000，通过 iframe 嵌入门户。                       

- 两套后端：门户 9099 和小智 8000，通过单点登录和摄像头桥接接口通信。                               
  
  这种“不同框架 + 清晰接口边界”的微前端方式，不等于代码没有合并。现在源码已经统一在一个 Git 仓库里，维
  护时修改对应的实际目录即可。                                                                        
  
  只有在以下情况才值得迁移到 Vue：                                                                    

- 小智页面准备长期持续增加大量业务功能。                                                            

- 多人同时维护前端，需要统一组件、状态和工程规范。                                                  

- 希望复用门户的 Element Plus 组件、权限拦截和主题系统。                                            

- 准备彻底去掉 iframe，把小智页面作为门户原生路由运行。                                             
  
  如果以后迁移，应逐步做，不要一次性重写：                                                            
1. 先提炼登录、WebSocket、摄像头帧等公共接口。                                                      

2. 在 ruoyi-fastapi-frontend/src/views/xiaozhi 建立 Vue 页面壳。                                    

3. 按“健康记录 → 数据分析 → 设备管理 → 实时监测”顺序逐页迁移。                                      

4. 每迁移一页，保留原功能作为对照，验证通过后再移除对应原生页面。                                   

5. 全部页面功能一致后，再决定是否去掉 8000 的静态前端托管。                                         
   
   现阶段建议保留原生小智前端，只统一 API、登录、设计和启动流程。这样能继续使用已经验证过的版本，也避免
   为了技术形式一致而推翻工作正常的实时监测代码。
