# 智能视频分析平台快速开始

日常使用：先启动 Docker Desktop 和依赖容器，再双击项目根目录的 `start-local.cmd`，最后在浏览器打开：

```text
http://localhost:5173/
```

本文 PowerShell 命令默认在项目根目录执行，需要管理员权限的步骤会单独注明。本机项目路径为 `E:\Learning\AA_Project\Binhua\Vibration-Image-Emotion-Analysis-main`；在其他电脑上请替换为实际路径。

## 1. 系统组成

| 组件     | 技术                          | 默认端口 | 源码位置                            |
| ------ | --------------------------- | ---- | ------------------------------- |
| 门户前端   | Vue 3 + Vite + Element Plus | 5173 | `ruoyi-fastapi-frontend/`       |
| 门户后端   | Python FastAPI              | 9099 | `ruoyi-fastapi-backend/`        |

## 2. 日常启动

### 2.1 启动依赖服务

先启动 Docker Desktop，再启动缓存和消息队列：

```powershell
docker start binhua-redis binhua-rabbitmq
```

`start-local.cmd` 会检查本机 `3306` 的 MySQL。服务停止时自动启动；权限不足时出现 Windows 管理员授权提示，允许后继续等待端口就绪。已正常监听时直接复用现有服务。

默认服务名为 `mysql`。如果本机使用其他服务名，先查询实际服务，再在 `ruoyi-fastapi-backend/.env.dev` 中设置 `MYSQL_SERVICE_NAME=实际服务名`：

```powershell
Get-Service | Where-Object { $_.Name -like "mysql*" }
```

本机已配置 MySQL 故障自动恢复。首次部署或迁移到其他电脑时，在**管理员 PowerShell** 中执行一次；日常启动无需重复配置：

```powershell
cd "E:\Learning\AA_Project\Binhua\Vibration-Image-Emotion-Analysis-main"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\configure_mysql_recovery.ps1" -ServiceName mysql
sc.exe qfailure mysql
```

服务名不同时，两条命令中的 `mysql` 都应替换为实际名称。设置成功后，`qfailure` 会显示三条 `RESTART`，延迟依次为 `5000`、`15000`、`60000` 毫秒。

脚本会保留开机自动启动和故障恢复设置，首次、第二次、后续异常退出分别等待 5 秒、15 秒、60 秒重新启动服务；手动正常停止服务不会触发故障恢复。本机曾出现电脑从睡眠恢复后 MySQL 异常退出，开机自动启动无法处理这种运行中的故障。这项设置用于自动恢复连接，底层异常仍需结合 MySQL 和 Windows 日志排查，详见第 6.5 节。

### 2.2 启动完整系统

双击：

```text
Vibration-Image-Emotion-Analysis-main\start-local.cmd
```

默认端口下，脚本会检查或启动：

1. 检查并按需启动本机 MySQL：3306
2. 小智便携 MySQL：3307
3. 门户后端：9099
4. 小智后端：8000
5. 疲劳推理服务：9101
6. Vue 前端：5173

脚本会检查门户后端、小智后端和疲劳服务的 HTTP 接口，再启动前端。模型首次加载可能超过 30 秒；如果等待超时，启动窗口会显示 `Warning`，此时应结合第 4 节的接口检查和日志确认状态。

<mark>不要同时运行</mark> `xiaozhi-study\start.cmd`，否则可能启动第二套小智服务。

### 2.3 打开系统

浏览器访问：

```text
http://localhost:5173/
```

如果曾关闭或重启过后端，使用 `Ctrl + F5` 强制刷新页面。

### 2.4 关闭系统

日常关闭使用项目自带的停止入口：

```powershell
cd "E:\Learning\AA_Project\Binhua\Vibration-Image-Emotion-Analysis-main"
.\stop-local.cmd
```

默认 `app` 模式按程序路径识别并停止本项目的应用进程，保留数据库和缓存。也可先预览将关闭的进程：

```powershell
.\stop-local.cmd --dry-run
```

如需同时关闭项目内的小智便携 MySQL 等数据库进程，使用：

```powershell
.\stop-local.cmd all
```

两种模式均保留系统 MySQL `3306` 和 Docker Redis/RabbitMQ；若脚本报告仍有端口占用，按输出检查对应进程。只有需要完全关闭本机依赖时，才在**管理员 PowerShell** 中继续执行：

```powershell
docker stop binhua-redis binhua-rabbitmq
Stop-Service mysql
```

手动停止 MySQL 后，下次运行 `start-local.cmd` 会再次尝试启动；Docker 容器需要按第 2.1 节重新启动。

### 3.3 初始化门户数据库

仅用于首次安装或明确需要重置的测试环境。以下命令会删除并重建 `ruoyi_fastapi`，SQL 文件也会重建系统表；已有业务数据时请保留现有数据库，先备份再制定迁移方案。

首次安装时，先在管理员 PowerShell 中启动 MySQL：

```powershell
Start-Service mysql
```

```powershell
$mysql = "D:\AA_install\mysql-8.0.44-winx64\bin\mysql.exe"
$project = "E:\Learning\AA_Project\Binhua\Vibration-Image-Emotion-Analysis-main"

& $mysql -h 127.0.0.1 -P 3306 -u root -p `
  --default-character-set=utf8mb4 `
  -e "DROP DATABASE IF EXISTS ruoyi_fastapi; CREATE DATABASE ruoyi_fastapi DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

& $mysql -h 127.0.0.1 -P 3306 -u root -p `
  --default-character-set=utf8mb4 `
  ruoyi_fastapi `
  -e "source $project/ruoyi-fastapi-backend/sql/ruoyi-fastapi.sql"
```

`--default-character-set=utf8mb4` 必须保留，否则 SQL 和页面中文可能乱码。

验证中文：

```powershell

  --default-character-set=utf8mb4 `
```

## 5. 摄像头和数据监控

数据监控支持三种来源：

- 小智摄像头
- 本机摄像头
- 海康 RTSP 摄像头

本机摄像头默认使用索引 `0`。如果电脑有多个摄像头，使用 FFmpeg 查看设备：

```powershell
& "D:\AA_install\EV\EVCapture\ffmpeg.exe" `
  -hide_banner -list_devices true -f dshow -i dummy
```

如果默认设备不是需要的摄像头，在 `.env.dev` 中调整：

```env
LOCAL_CAMERA_INDEX=0
```

修改后需要重启门户后端。

切换到小智摄像头后，前端会断开旧 MJPEG 视频流，后端会关闭本机摄像头采集线程。若摄像头指示灯仍亮，检查：

- 是否同时打开多个监控标签页
- vivo 办公套件、会议软件或相机应用是否占用摄像头
- 页面是否已经 `Ctrl + F5`

实时监测的数据链路：

```text
摄像头帧
├─ OpenCV SSD 人脸检测
│  └─ 人脸稳定门控
│     └─ PP-YOLOE_plus-S_face 检测
│        └─ ResNet50_face 特征提取
│           └─ 与已登记人员特征做余弦相似度匹配
└─ VibraimageCore
   └─ 帧差、ROI 振幅、Welch 频谱和统计公式
      └─ e1-e14、幸福指数和预警结果
```

模型说明：

- `PP-YOLOE_plus-S_face` 和 `ResNet50_face` 是 PaddleX 官方预训练模型。
- 人脸特征保存在数据库表 `xuzhou_people_face`。
- 实时视频识别阈值约为 `0.4`，人员匹配默认限定第 1 组。
- `e1-e14` 是振动图像统计公式的结果，不是神经网络输出。
- 当前仓库没有现场训练的人脸、情绪或声纹模型。
- 多模态 AI 助手使用远程 `qwen3-omni-flash`，只负责对话，不参与人脸识别或 e1-e14 计算。

模型缓存默认位于：

```text
.runtime\paddlex\official_models
```

通过其他方式直接运行 `app.py` 时，缓存可能位于用户目录：

```text
C:\Users\<用户名>\.paddlex\official_models
```

模型权重体积较大，保存在本机或发布包中，不提交 Git。

## 6. 常见问题

### 6.1 打开后显示 404

只能从门户首页进入：

```text
http://localhost:5173/
```

以下地址返回 404 是正常的，它们不是网页入口：

```text
http://localhost:5173/dev-api/
http://127.0.0.1:9099/
```

### 6.2 小智页面显示 503

通常是 `8000` 未启动，或者小智运行时缺少 `.runtime`、`.venv`。

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8000
Get-Content ".runtime\logs\xiaozhi.err.log" -Tail 100
```

重新运行根目录 `start-local.cmd`，不要只启动门户。

### 6.3 接口出现 Axios 10 秒超时

先强制刷新页面。启动脚本会检查 `9099` 和 `8000` 的 HTTP 状态，等待超时会输出 `Warning`；设备列表查询已设置为 20 秒并避免请求重叠。出现 `Warning` 时，先确认对应后端的接口和日志。

如果持续超时，检查：

```powershell
Invoke-WebRequest http://127.0.0.1:9099/openapi.json
Invoke-WebRequest http://127.0.0.1:8000/
```

同时查看：

```text
.runtime\logs\backend.err.log
.runtime\logs\xiaozhi.err.log
.runtime\logs\frontend.err.log
```

### 6.4 本机摄像头没有画面

检查设备是否被其他程序占用，并确认索引正确：

```powershell
Get-PnpDevice -Class Camera -PresentOnly
```

如果笔记本摄像头和手机办公套件同时存在，`0` 通常是笔记本摄像头，`1` 可能是手机或虚拟摄像头。

### 6.5 MySQL 未监听或认证失败

#### MySQL is not listening on 127.0.0.1:3306

该提示表示启动脚本无法连接数据库端口。先在项目根目录检查服务状态和端口：

```powershell
Get-Service -Name mysql | Select-Object Name, Status, StartType
Test-NetConnection -ComputerName 127.0.0.1 -Port 3306
```

正常结果应为 `Status=Running`、`TcpTestSucceeded=True`。本机日志曾记录睡眠恢复后 MySQL 多次异常退出；即使启动类型为 `Automatic`，没有故障恢复策略时仍会保持停止状态。

处理步骤：

1. 重新运行 `start-local.cmd`。服务停止时脚本会尝试启动，出现 Windows 管理员授权提示时允许。
2. 如果提示找不到服务，查询 `Get-Service -Name 'mysql*'`，核对 `.env.dev` 的 `MYSQL_SERVICE_NAME` 与实际安装相符。
3. 如果取消过授权，重新运行并允许，或在管理员 PowerShell 中执行 `Start-Service mysql`。
4. 反复在睡眠恢复后发生时，按第 2.1 节配置故障自动恢复，再用 `sc.exe qfailure mysql` 验证三条 `RESTART` 设置。
5. 如果服务已运行却仍无法连接，核对 `.env.dev` 的 `DB_HOST`、`DB_PORT` 和 MySQL 实际监听地址、端口，并查看 MySQL 错误日志。

查看最近的服务异常退出记录：

```powershell
Get-WinEvent -FilterHashtable @{
  LogName = 'System'
  ProviderName = 'Service Control Manager'
  Id = 7034
  StartTime = (Get-Date).AddDays(-7)
} -ErrorAction SilentlyContinue |
  Where-Object { $_.Message -match 'mysql' } |
  Select-Object TimeCreated, Message
```

本文部署使用门户 MySQL `3306`。小智的 `3307` 是独立数据库；旧便携部署的 `13306` 需要额外的 MariaDB 程序和数据目录，调整端口前应确认实际数据库位置。

#### MySQL Access denied

此时应核对数据库账号、密码和授权。确认 `.env.dev` 中的 `DB_USERNAME`、`DB_PASSWORD`、`DB_DATABASE` 与现有数据库一致；修改后重启门户后端。也可先确认服务状态：

```powershell
Get-Service mysql
```

### 6.8 人员信息上传失败

`xuzhou_people_face.group_id` 指向 `xuzhou_people_group.id`。实时识别默认使用第 1 组，缺少分组时先创建：

```powershell
$mysql = "D:\AA_install\mysql-8.0.44-winx64\bin\mysql.exe"

& $mysql -h 127.0.0.1 -P 3306 -u root -p `
  --default-character-set=utf8mb4 `
```

其他常见原因包括照片中没有清晰人脸、文件不是 JPG/PNG，或 PaddleX 模型首次加载失败。

### 6.9 AI Agent 无法回答

确认 `.env.dev` 中的 `DASHSCOPE_API_KEY` 有效，并检查服务器能否访问阿里云百炼。

### 6.10 模型依赖安装失败

使用项目指定的 Python 3.12，检查磁盘空间和网络。默认使用 CPU 版 PaddlePaddle；没有 GPU 环境时不要安装 CUDA 版依赖。
